5. ROOT-CAUSE-FIRST RULE
============================================================

Always prefer fixing the root cause instead of applying a superficial
patch.

Before coding, determine why the problem exists.

Bad approach:
- Hide an incorrect value in the frontend.
- Add a frontend-only calculation.
- Hardcode a value.
- Add duplicate business logic.
- Add a temporary workaround.
- Change CSS to hide a functional problem.

Correct approach:
- Find the actual source of the problem.
- Fix the correct layer.
- Update all dependent layers.
- Verify the complete flow.

10. SOCIETY FUNCTION MANAGER ROLE SECURITY
============================================================

There are two roles:

1. ORGANIZER / ADMIN
2. FLAT OWNER / USER

Organizer/Admin can access authorized society management and financial
functionality.

Flat Owner/User must NEVER receive Organizer-only financial information.

Do not merely hide financial UI elements.

Enforce authorization on the backend/API.

Verify:

- UI access
- Route access
- API access
- Backend authorization
- Returned JSON data
- Direct URL access
- Unauthorized requests
- Browser state
- Local storage/session data
- Downloadable reports
- Network responses

A Flat Owner/User must not receive protected financial data even if
the frontend hides it.


============================================================
11. FINANCIAL DATA LEAKAGE RULE
============================================================

Do NOT return protected financial fields to unauthorized users and then
hide them with frontend code.

Bad:
API returns all financial information → frontend hides it.

Correct:
Backend checks role → backend returns only permitted information.
